A tela **Integrações** conecta contas de apps externos ao projeto pelo
**Composio**, um catálogo com mais de mil apps (Google Agenda, Gmail, HubSpot,
Notion, Pipedrive, Calendly…). Depois de conectada, a conta pode ser usada pelo
agente como **tool**: consultar a agenda, criar um negócio no CRM, gravar numa
planilha. Esta página cobre a conexão. Escolher as tools e colocá-las no agente
está em [Tools: Composio](/engenharia-de-ia/tools/composio).

## Onde fica no painel

Menu **Integrações** (`/integrations`). A tela lista os apps com busca, filtro por
categoria e ordenação (**Mais usadas**, **Nome (A–Z)**, **Conectadas primeiro**).
Os conectados mostram **Conectado**.

Só **admin** e **editor** conectam e desconectam.

## Como configurar

<Steps>
<Step title="Abra o projeto certo">
A conexão é do **projeto** aberto no painel, não da conta da agência. Confira o
nome do projeto antes de conectar.
</Step>
<Step title="Encontre o app">
Busque pelo nome. Se não aparecer, veja "Que apps existem?" abaixo.
</Step>
<Step title="Clique em Conectar">
Há dois jeitos, conforme o app:

- **OAuth:** abre uma janela do próprio app (Google, HubSpot…) para a pessoa
  entrar e autorizar. Ao fechar, o card passa a mostrar **Conectado**.
- **Credencial:** abre um formulário pedindo a chave de API, o token ou usuário e
  senha do app. Os campos vêm do próprio app.
</Step>
<Step title="Confira as tools">
No card do app, abra a lista de tools que ele oferece. Para o agente usar,
adicione as tools no editor do agente e publique a versão.
</Step>
</Steps>

### Desconectar

No card conectado, **Desconectar**. O agente perde acesso às ações daquele app até
a conta ser conectada de novo. No LangChain Agent, as tools do app continuam no
config e o modelo continua vendo-as: quando ele chama uma, a chamada falha e ele
recebe o erro. Tire as tools do agente se a conta não vai voltar.

## Como funciona por trás

- **A conta fica presa ao projeto.** Cada projeto tem as próprias conexões. Conectar
  o Google Agenda no projeto A não vale para o projeto B. Um projeto nunca usa a
  conta de outro.
- **Uma conexão por app por projeto.** Para trocar a conta (outro e-mail, outra
  empresa), desconecte e conecte de novo.
- Tentativas antigas que não terminaram (expiradas ou com falha) são limpas quando
  se conecta de novo.
- O catálogo é atualizado a cada hora.
- **Ficam fora do catálogo:** WhatsApp (o canal já é da Zatten), os toolkits
  internos do Composio e apps que não pedem autenticação.
- **Entram:** apps com OAuth gerenciado pelo Composio, ou com credencial do tipo
  chave de API, token (Bearer) ou usuário e senha.

## Que apps existem?

O catálogo público do Composio lista todos os toolkits, com o slug, o número de
tools, o tipo de autenticação e se o Composio gerencia o OAuth:

- **Tabela completa (melhor para IA):** https://docs.composio.dev/toolkits, também
  em Markdown em https://docs.composio.dev/toolkits.md
- **Página de um toolkit:** `https://docs.composio.dev/toolkits/<slug>` (ex.:
  https://docs.composio.dev/toolkits/googlecalendar), com as tools e os parâmetros.

Para saber se um app serve ao caso do cliente, abra a página do toolkit e procure a
tool que faz a ação (ex.: "create event", "find free slots"). Depois confira se ele
aparece na tela Integrações: só os de OAuth gerenciado ou credencial aparecem.

<Visibility for="agents">
Na tela, o app é identificado pelo slug do toolkit em minúsculas (ex.:
`googlecalendar`, `hubspot`). No config do agente, a tool Composio é
`{ "type": "composio", "toolkit": "<slug>", "action": "<ação>" }`, em minúsculas; o
modelo vê o nome `TOOLKIT_ACTION`. Estados da conexão vindos do Composio: `ACTIVE`
(conectado), `INITIATED`, `EXPIRED`, `FAILED`. Só `ACTIVE` vale.
</Visibility>

## Pelo MCP

A conexão **não viaja** no template: ela é uma autorização da conta do cliente
final, não configuração. O que viaja são as tools Composio dentro do bloco
`langchain`. Ao aplicar um template num projeto onde o app não está conectado, as
tools entram no agente mesmo assim, e cada chamada falha até alguém conectar a conta
pela tela Integrações. Conecte antes de publicar a versão.

Conectar é sempre uma pessoa, no painel: o OAuth pede o login do dono da conta.
O assistente só guia.

## Armadilhas

- **Conectar com a conta errada.** A conta conectada é a que o agente usa para
  todos os leads. Conecte com a conta do cliente final (a agenda da clínica), não
  com a da agência.
- **Projeto errado aberto.** A conexão vai para o projeto do painel. Confira o nome
  antes.
- **Conectar não basta.** O agente só usa o app depois de as tools estarem no
  config e a versão ser publicada.
- **Token expirado do lado do app.** Se o dono trocar a senha ou revogar o acesso,
  a conexão para de funcionar. Desconecte e conecte de novo.
- **Duplicar ou importar o projeto** leva as tools, mas não a conexão. Conecte de
  novo no projeto novo.

## Perguntas frequentes

<AccordionGroup>
<Accordion title="O app que eu quero não aparece na tela. E agora?">
Confira em https://docs.composio.dev/toolkits.md se ele existe e qual o tipo de
autenticação. Se não aparece na tela, use uma tool HTTP para a API do app
([Tools: HTTP](/engenharia-de-ia/tools/http)).
</Accordion>
<Accordion title="O Composio cobra?">
Não. As conexões pela tela Integrações não têm custo nem limite de uso para a
agência. Você pode conectar quantos apps quiser no projeto, com **uma conta por
app** (por exemplo, um Gmail por projeto).
</Accordion>
<Accordion title="Os dados do lead passam pelo Composio?">
Passam os parâmetros que o agente envia na tool (ex.: nome e horário para criar um
evento). Avalie isso com o cliente final, como em qualquer integração.
</Accordion>
</AccordionGroup>
