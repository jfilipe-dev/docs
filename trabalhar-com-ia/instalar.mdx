<Visibility for="agents">
**Quando ler esta página:** quando for conectar um assistente de IA à Zatten. Se você é o assistente e a pessoa colou o prompt de instalação, vá direto a **Passo a passo por assistente**, siga a seção do seu assistente e depois comece o [setup](/trabalhar-com-ia/setup). Esta página só pede para instalar: o token nunca vai para arquivo nem para a conversa, e nunca use `--scope project`.
</Visibility>

Conectar um assistente à Zatten leva três peças: as **skills do Zatten-OS**
(`zatten-ops`, `zatten-comercial`, `zatten-agencia` e `zatten-grill`), o **MCP da
Zatten** e o **MCP da doc**. O jeito mais curto é criar uma conexão no painel e
colar o prompt de instalação no assistente: ele instala a skill e o MCP da Zatten
e confirma listando os seus projetos.

## Antes de começar

- **Só o admin da conta** vê **Configurações → Conectar ferramentas de IA**. Uma
  conexão pode alcançar todos os projetos da conta, por isso os outros papéis não
  criam conexões.
- **Assistentes aceitos:** Claude Code, Codex, Cursor e outros que aceitem servidor
  MCP por HTTP com cabeçalho. O ChatGPT e o Claude Desktop ainda não entram: eles
  exigem login por OAuth, que está em construção.

## Criar a conexão e instalar

<Steps>
  <Step title="Abra a tela">
    No painel, abra o menu do seu usuário e vá em **Configurações → Conectar
    ferramentas de IA**.
  </Step>
  <Step title="Crie uma conexão">
    Preencha:
    - **Nome:** só para reconhecer a conexão na lista (por exemplo, "Claude do João").
    - **Quais projetos esta conexão alcança:** *Todos os projetos da conta,
      inclusive os futuros*, ou *Apenas os projetos que eu escolher*.
    - **Permissão:** *Somente leitura* (consulta e não muda nada) ou *Leitura e
      edição* (também cria e altera, cria projetos e testa o agente, mas nunca
      apaga, nunca publica o agente e nunca envia template à Meta). Para criar
      projetos, a conexão precisa alcançar todos os projetos da conta.
  </Step>
  <Step title="Copie o prompt e o token">
    A tela **Conexão criada** mostra duas coisas separadas: o **prompt de
    instalação** (já com o endereço do servidor) e o **token**. O prompt não leva
    o token dentro: assim ele pode ser compartilhado sem risco. O token aparece
    mascarado e vai inteiro ao copiar.
  </Step>
  <Step title="Cole o prompt no assistente">
    O assistente vai pedir o token antes de continuar: cole quando ele pedir. Com
    ele, o assistente instala a skill e o MCP da doc, adiciona o servidor MCP
    `zatten` e confirma.
  </Step>
  <Step title="Reinicie se ele pedir">
    Um MCP recém-adicionado costuma só aparecer depois de reiniciar a sessão do
    assistente. Se ele pedir, reinicie e diga para continuar.
  </Step>
  <Step title="Confira a conta e os projetos">
    O assistente chama `whoami` e `list_projects` e diz em nome de qual conta age,
    se pode alterar ou só ler, e quais projetos apareceram. Se são os que você
    marcou, está pronto. Em seguida ele começa o [setup](/trabalhar-com-ia/setup):
    conhece a agência, organiza as pastas e propõe uma primeira vitória, sem
    alterar nada sem o seu "sim".
  </Step>
</Steps>

<Warning>
**Copie o token na hora.** A Zatten guarda só uma assinatura dele. O token não
aparece de novo, nem para o suporte. Se perder, crie outra conexão; a antiga
continua funcionando até ser revogada.
</Warning>

<Accordion title="O prompt de instalação, na íntegra">
`<endereço do servidor>` é o que a tela preenche com o domínio do seu painel. O
prompt é curto de propósito: os comandos de cada assistente estão abaixo, em
**Passo a passo por assistente**.

```text
Conecte a Zatten neste ambiente.

Você vai precisar do meu token da Zatten. Se eu ainda não colei um nesta
conversa, PERGUNTE antes de continuar — eu gero no painel, em
Configurações → Conectar ferramentas de IA. Nunca repita o token na
resposta e nunca o grave em arquivo deste projeto.

1. Leia https://docs.zatten.com/trabalhar-com-ia/instalar.md e siga os passos do
   seu assistente: instale as skills do Zatten-OS (repositório zatten-ai/zatten-os),
   o MCP da documentação e o servidor MCP da Zatten, no endereço
   <endereço do servidor>
   com o cabeçalho Authorization: Bearer <o token>. Configure no escopo do
   usuário, nunca --scope project.
2. Se as ferramentas da Zatten ainda não aparecerem, me peça para reiniciar a
   sessão e continue depois.
3. Chame whoami e list_projects e me diga: em nome de qual conta você age, se
   pode alterar ou só ler, e quais projetos apareceram.
4. Use a skill zatten-ops para começar o setup (https://docs.zatten.com/trabalhar-com-ia/setup.md).
   Não altere nada sem o meu "sim".
```
</Accordion>

O endereço do servidor usa o domínio em que você está no painel. Numa conta
white-label, o prompt já sai com o domínio da agência.

### Instalar à mão

Na mesma tela, **Instalar manualmente** mostra o comando da skill, o endereço do
servidor e um trecho de configuração no formato aceito pela maioria dos
assistentes. Use se preferir
conferir antes de deixar o assistente mexer na própria configuração. O token
continua vindo só da tela de criação.

## Passo a passo por assistente

Três coisas, em qualquer assistente:

1. **As skills do Zatten-OS**, do repositório `zatten-ai/zatten-os`.
2. **O MCP da doc**, público e sem token: `https://docs.zatten.com/mcp`, com o nome
   `zatten-docs`.
3. **O MCP da Zatten**, por HTTP, com o nome `zatten`, no endereço que o painel
   mostra e o cabeçalho `Authorization: Bearer <token>`. Sempre no escopo do
   **usuário**: nunca num arquivo dentro de um projeto ou repositório.

Depois, reinicie a sessão se as ferramentas não aparecerem, e confira com `whoami`
e `list_projects`.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    # skills + MCP da doc (o plugin já traz o MCP da doc)
    claude plugin marketplace add zatten-ai/zatten-os
    claude plugin install zatten-os@zatten-os

    # MCP da Zatten, no escopo do usuário (o padrão). Nunca --scope project.
    claude mcp add --transport http zatten <endereço do servidor> \
      --header "Authorization: Bearer <token>"
    ```

    Depois de instalar, `/reload-plugins` ou uma sessão nova.
  </Tab>
  <Tab title="Codex">
    ```bash
    npx skills add zatten-ai/zatten-os --skill '*' -g
    ```

    Em `~/.codex/config.toml` (o arquivo do usuário, fora de qualquer projeto):

    ```toml
    [mcp_servers.zatten-docs]
    url = "https://docs.zatten.com/mcp"

    [mcp_servers.zatten]
    url = "<endereço do servidor>"
    http_headers = { Authorization = "Bearer <token>" }
    ```
  </Tab>
  <Tab title="Cursor e outros">
    ```bash
    npx skills add zatten-ai/zatten-os --skill '*' -g
    ```

    Na configuração de MCP do **usuário** (no Cursor, `~/.cursor/mcp.json`; em
    outros assistentes, o arquivo equivalente fora do projeto):

    ```json
    {
      "mcpServers": {
        "zatten-docs": { "url": "https://docs.zatten.com/mcp" },
        "zatten": {
          "url": "<endereço do servidor>",
          "headers": { "Authorization": "Bearer <token>" }
        }
      }
    }
    ```
  </Tab>
</Tabs>

A skill sozinha não acessa nada: quem carrega a credencial da conta é o MCP da
Zatten. Sem o MCP da doc, o assistente lê `https://docs.zatten.com/llms.txt` e as
páginas em Markdown (acrescentando `.md` ao endereço).

## Manter a skill atualizada

A skill muda pouco, mas muda. Cada método se atualiza de um jeito:

| Método | Atualizar |
|---|---|
| Plugin do Claude Code | Ligue a atualização automática do marketplace `zatten-os`. Ela vem desligada para marketplaces de terceiros. À mão: `claude plugin update zatten-os@zatten-os` |
| `npx skills` | Sempre à mão: `npx skills update -g` |


## Ver e revogar conexões

A tela lista cada conexão numa linha: o nome, se **lê e altera** ou é **somente
leitura**, quais projetos alcança e quando foi usada pela última vez.

Para revogar, clique na lixeira da conexão. O assistente perde o acesso na hora.
Não dá para desfazer: para reconectar, crie outra conexão.

Para trocar a permissão ou os projetos de uma conexão, crie uma nova com o alcance
certo e revogue a antiga.

## Armadilhas

- **"Todos os projetos" inclui os futuros.** Um projeto criado amanhã já fica ao
  alcance da conexão. Para limitar, escolha os projetos.
- **Já tinha uma versão anterior?** A skill `zatten` (2.x) virou `zatten-os` (3.x),
  e a `zatten-os` virou `zatten-ops` (4.x), ao lado de `zatten-comercial`,
  `zatten-agencia` e `zatten-grill`. No Claude Code, atualize o plugin
  (`claude plugin update zatten-os@zatten-os`); se ainda tiver o plugin
  `zatten@zatten`, desinstale. Com `npx skills`, `npx skills remove zatten zatten-os`
  e instale de novo com o comando acima.
- **Somente leitura recusa toda escrita.** O assistente recebe "Este token é
  somente leitura". Crie uma conexão com *Leitura e edição* se a agência quiser
  que ele altere projetos.
- **Projeto fora do alcance não aparece.** Se `list_projects` não mostra um
  projeto, não há como lê-lo nem alterá-lo por essa conexão, nem pelo id.
- **O token é da conta, não de uma pessoa.** Quem tiver o token age em nome da
  conta. Não cole o token em arquivos versionados nem em conversas
  compartilhadas.
- **`--scope project` vaza o token.** No Claude Code, adicionar o MCP com
  `--scope project` grava o token num `.mcp.json` dentro do repositório, e ele
  vai parar num commit. Use o escopo padrão (do usuário).
